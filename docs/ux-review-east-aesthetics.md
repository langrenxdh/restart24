### 结构总评:起承转合

- **起(晨)**:三步唤醒是货真价实的微仪式——一屏、一句、一个按钮;但四屏同构无渐强,「今天只做一件事」这个 peak 没有被抬起来。
- **承(专注)**:承诺 → 大数字 → 钟声 → 记成果,是全应用唯一完整的仪式闭环,最接近一期一会。
- **转(复位/应急)**:功能到位,形制全是表单;「换挡」与「失控」两种戏剧性时刻,与晨间屏共用同一张脸。
- **合(晚)**:十屏连环收束到「明天见。」,收得干净;但入夜即满屏表单,缺一个「暮」的转场。
- 结论:**不是六个表单**——计时屏、两座大字收束屏已经破了表单骨架;但「转」「合」的路径屏仍是骨架复制,叙事节奏目前由文案独力支撑,视觉未跟上。

## 二、成立的资产(必须保留)

1. **纸-墨-赭-苔四色令牌**(styles.css `@theme`):正文墨 `#33291c`、辅文淡墨 `#7c6c53`、行动赭 `#c05f1c`、胜利苔 `#6f7a4d`——这套色板本身就是「墨分五色」的克制:大面积只有纸与墨,彩色只做点睛。**不要增加第五种色相。**
2. **灰色胜利的灰字处理**(WinMoment):赢用赭、守住用淡墨,以墨色浓淡叙事而不动布局——这是全应用最成熟的一处东方表达,后续任何「庆祝强化」都应向它看齐,而不是向花哨看齐。
3. **计时屏构图**(FocusFlow running):承诺小字在上、88px 大数字独占中心、仅两条退路——「一次只做一件事」的视觉化身,全应用留白之最。
4. **合成钟声**(chime.ts):C5-E5-G5 正弦、0.18s 错峰、1.1s 指数衰减,零音频资源——器物感的听觉锚点,应复用到晚间「明天见」(见 P7)。
5. **display / 正文双字体分工**:界面语用黑体(PingFang),心语(MIT、交付物、承诺)用宋体系(Georgia→Songti)——用户写下的字落在宋体里,像砚上题字,方向完全正确。
6. **六字 / 三字大字收束屏**:「我赢了。」「时间到。」「明天见。」——以文为印、以留白为饰,比任何插图都东方,是本产品的视觉签名。
7. **教练文案的底色**:「这是数据,不是罪状」「回来就算数」「错过早晨仪式?不算事」——永不责备已内化进字里行间,声韵克制而准确。
8. **细节**:`theme-color #f8f2e7` 让状态栏与纸同色;`-webkit-tap-highlight-color: transparent`;按钮 `active:scale` 微收——指感已有「按」的物质性。

## 三、改进清单(按影响力排序)

### P1 赢的时刻:朱砂一点 + 清场 ⭐ 最高优先
- **位置**:`src/components/WinMoment.tsx` + `src/App.tsx`(InstallGuide / notice 渲染条件)
- **现状(证据)**:庆祝屏 h1 赭橙 60px 满字;上方叠安装卡(15:00 走查 innerText 顺序:安装文案在「我赢了。」之前)与 21:30 时的「睡前 45 分钟」notice;无任何动效(全应用仅有 `active:scale`)。
- **建议**:
  1. 清场:`mode === 'won'` 或 view 为庆祝态时,不渲染 InstallGuide 与 notice(App.tsx 两个条件各加一个布尔),让「我赢了。」独占一屏;
  2. 朱砂一点:成果卡右下角加一枚 CSS 方印——`<span>` 内字「赢」(灰色胜利用「守」),规格:28×28px、`border 1.5px solid #c05f1c`、赭字、`border-radius: 2px`、`transform: rotate(-4deg)`、`opacity: .85`、display 字体 15px;
  3. 盖印动效:印初始 `scale(2.2) opacity 0`,`180ms cubic-bezier(.2,1.4,.4,1)` 落至 `scale(1)`,延迟 250ms(大字先立,印后落);整屏 h1 加 `300ms fade + translateY(8px)` 入场;
  4. 同时 `playChime()`(已有函数,一行)——钟、印、字三事齐,火候即到。
- **为什么**:仪式感(赢是全应用唯一的「节日」)、色彩的分寸(朱砂一点 vs 整行赭橙大字——当前 h1 用行动色,还与热力图的胜利色苔绿相冲突:同一件事两种彩色,墨色系统就破了)。

### P2 成果墙:从 Excel 到庭园
- **位置**:`src/components/WinWall.tsx` 热力图部分
- **现状(证据)**:43.7px 方格 + 圆角 8px + 每格 12px 数字(赢格白字数字),星期表头 + 图例 + 「本月 N 胜」计数行,整体是 GitHub 式贡献格。
- **建议**:
  1. **数字退位**:赢格与灰色胜利格**不再显示日期数字**(那一天的分量交给颜色),仅未记录格保留 11px `text-ink-soft/50` 数字作定位;
  2. **浓度分级**:赢格按当日 deliverables 数分两档墨色——1 个 `bg-moss/70`,≥2 个 `bg-moss`(苔痕由浅入深,「墨分五色」的浓淡叙事);灰色胜利维持 `bg-ink-soft/50`;
  3. **呼吸**:`gap-1.5`→`gap-2`(6→8px),格子 `rounded-lg`→`rounded-md`(8→6px),弱化「单元格」感;
  4. **月份题款**:「2026 年 9 月」改 display 字体 + `tracking-widest`,下加「本月八胜」汉字数词(8→八,一~三十一的简单映射,10 行 JS);
  5. 点开某天的详情卡(现有)即「掀开一块苔」——已成立,保留。
- **为什么**:时间性(成果墙应是回望的庭园,不是绩效考核表);留白与密度(数字满格 = 每块石头都贴了标签)。

### P3 数字改用宋体 lining 字形(修「老式数字」之恙)
- **位置**:`src/styles.css`(`.tnum` 与 `--font-display`)、FocusFlow/EmergencyFlow 计时、App header 连胜、WinWall 月份与统计
- **现状(证据)**:canvas 实测 88px Georgia——数字 3/4/5/7/9 的 baseline 下沉 16px、上伸仅 47px,而 0/1/2 贴基线;即倒计时「24:59」中 4、5、9 悬在基线之下,大字号下基线明显晃动;且 Android 无 Georgia,回退 Noto Serif SC 的全高 lining 数字——**跨端两副面孔**。宋体(Songti SC)数字为全高 lining(实测上伸 61px),与中文字面同高。
- **建议**:
  1. 计时与所有统计数字:`font-family: "Songti SC", "Noto Serif SC", Georgia, serif`(把中文字体提到最前,拉丁数字即用宋体自带衬线数字),保留 `.tnum` 对齐;
  2. 或者最小改动:仅 `.tnum` 加 `font-feature-settings: "lnum" 1`(注:Georgia 多数字重不含 lining 备选字形,此法在部分平台无效——故推荐前者为准);
  3. header「连胜 N」改 display 字体并写作「连胜 · N 日」,与器物口径统一。
- **为什么**:纸墨质感(数字是全应用最大的字,却是最不「器物」的字形;宋体数字与宋体标题同出一脉,混排之「隔」立即消解)。

### P4 暮色:让时间进入纸面
- **位置**:`src/App.tsx`(按 hour 设置属性)+ `src/styles.css`
- **现状(证据)**:21:00、21:30、23:00 走查,所有屏 body 背景仍为亮纸 `rgb(248,242,231)`——深夜应急屏、晚间复盘屏与晨间屏同亮度。
- **建议**:
  1. `hour >= 20` 时 `document.documentElement.dataset.phase = 'evening'`,`>= 22` 设 `'night'`(useToday 已有 now,一行 effect);
  2. CSS:`html[data-phase='evening'] body { background-color: #efe5d2(paper-deep); background-image 的墨点 alpha 0.045→0.06 }`;`html[data-phase='night'] body` 再以 `color-mix(in srgb, #f8f2e7 94%, #33291c)` 沉一档;文字与彩色令牌不动——只让纸变旧,不让墨变淡;
  3. 晚间完成屏「明天见。」可加 `theme-color` meta 同步(可选)。
- **为什么**:时间性(昼夜是现成的、零成本的叙事维度;暮纸上的「明天见」与晨纸上的「闹钟响过了」构成一天的墨色对仗)。

### P5 TodayCard 枢纽:给「唯一」让出留白
- **位置**:`src/components/TodayCard.tsx` + `src/App.tsx`
- **现状(证据)**:14:00 一屏五个行动(赭主按钮 + 午间复位 + 直接记录 + 晚间流程 + 「今天崩了」链)加安装卡;「唯一的 MIT」标签 14px 与 h1 32px 之间,视觉重量被下方按钮列瓜分。
- **建议**:
  1. 保留「开始一轮专注」唯一主按钮;「直接记录交付物」降为与「今天崩了」同级的文字链(两行小链,`text-sm text-ink-soft/70`);
  2. 「午间复位」只在 resetOpen 时由 notice 横幅引导(该横幅机制已存在,复位按钮可撤——走查中两者同时出现是重复);
  3. h1 上下留白加倍:`mt-4`→`mt-6`,MIT 之后至按钮列之间保底 96px 空白(`mt-auto` 已有,补 `min-h`);
  4. 「今天已完成 N 轮专注 · M 分钟」改 display 字体、移到按钮列上方作「落款」行。
- **为什么**:留白与密度(「一次只有一件事」是产品哲学,枢纽屏却是全应用行动密度之最;留白不是浪费,是让 MIT 这件「事」被供起来)。

### P6 输入框:从白盒到笺纸
- **位置**:`MorningRitual.tsx` / `FocusFlow.tsx` / `ResetFlow.tsx` / `EmergencyFlow.tsx` / `EveningFlow.tsx` / `DeliverableLog.tsx` / `WinWall.tsx` 中所有 `bg-white/50` 输入(三处文件各自定义了相同的 `textareaCls/inputCls` 字符串——顺手可收敛到 ui.tsx 共享)
- **现状(证据)**:全部输入为白底半透明、16px 圆角、`border-ink/15`,在暖纸上是标准 Web 表单语汇;白色 `rgb(255,255,255)` 与纸 `rgb(248,242,231)` 的冷感之差肉眼可辨。
- **建议**:
  1. 输入底改 `bg-paper-deep/60`(或 transparent),边框 `border-ink/20`,圆角降为 `rounded-lg`(12px);
  2. **仅两处题字式输入升级为「笺」**:晨间 MIT 与晚间复盘问——去四边框,只留 `border-b border-ink/25`(底墨线),聚焦时 `border-ember/60`;这五行字是用户一天中最郑重的字,值得用砚台的线而不是表格的框;
  3. placeholder 从灰蓝系改 `text-ink-soft/60`,保持墨系。
- **为什么**:纸墨质感(白盒是「表单」,笺是「文房」);文案声韵(题字的场合应有题字的器)。

### P7 转场与钟声:仪式的呼吸
- **位置**:`src/components/ui.tsx`(Screen 基元)+ `EveningFlow.tsx` finish()
- **现状(证据)**:所有视图切换为 React 状态瞬切,无过渡;晚间完成「明天见。」无钟声(钟声目前只在计时结束)。
- **建议**:
  1. Screen 基元加统一入场:`animation: enter 280ms ease-out`(keyframes:opacity 0→1 + translateY(8px)→0),一行 CSS,全站所有屏同时受益;步骤屏(晨间三步、复盘五问)在 key 变化时重放;
  2. 晨间步骤切换可加 120ms 的「顿」(下一步延迟入场)——茶道的一期一会不在快,在节;
  3. `finish()` 落库成功后调 `playChime()`(已有)——一天的「合」应有钟。
- **为什么**:仪式感(转场即情绪缓冲;当前每个「合上」的时刻都来得太急,没有给告别留位置)。

### P8 文案声韵:三处微调
- **位置与建议**:
  1. `TodayCard.tsx`「今天崩了」→「今天乱了」——「崩」是彻底的自责词,与「永不责备」的底色相逆;「乱」可整理,语感可逆;
  2. `EveningFlow.tsx`「今天没了,直接排明天」→「今天不追了,排好明天」——「没了」有余烬感,「不追了」是主动收兵,更近教练的声口;
  3. `WinMoment.tsx` 加落款:成果卡右下(印之下)以 display 字体 12px 记「九月十四日 · 周一」(月日汉字化,`Intl` 数字转汉字十行内)——画有落款,赢有日期,胜利便成了「作品」;
  4. 保留不动:「就它了」「时间到。」「我赢了。」「明天见。」「铁律:上午做什么,下午继续做什么。」——这些是已经炼成的句子,一字不要动。
- **为什么**:文案声韵(教练式与诗意不冲突;冲突的是失控场景里的自责残留)。

### P9 节气与昼夜入 header(轻量)
- **位置**:`src/App.tsx` header + 新增 20 行 JS(节气表)
- **现状**:header 仅「9月14日 周一」sans 12px。
- **建议**:日期后缀当日至下一节气名(2026 年内的 24 节气日期表约 24 项,纯查表),「白露 · 九月十四日 周一」;晨间屏可作眉标。不引入图片、不引入历法库。
- **为什么**:时间性(节气是中国人的时间质感;一天一 MIT 的系统,配节气的时间观是「日日新」的底文)。

### P10 纸纹浓度(需人类复核截图)

- **现状**:墨点 alpha 0.045、22px 网格——数值上在暖纸对比度极低(墨 4.5% 透明度),2x 屏恐近不可见;走查 computed 值确认在渲染,但浓度是否「可感」我无法以样式值断言,请对照截图 `/tmp/ux-east-01` 与真机。

## 四、东方视角 Top 5(只改五处,改这五处)

1. **P1 朱砂印 + 庆祝屏清场**——赢是产品的节日,现在是节日里堆着杂物、喊着一整行橙色;一枚旋转四度的方印、一次 180ms 的落印、一声已有的钟,「热闹」就到了火候。
