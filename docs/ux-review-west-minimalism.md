## 二、成立的资产（达到好的功能主义标准，必须保留）

1. **令牌化的极简色彩/字体系统**：6 色 + 2 字体族，全应用无一个游离色值；纸面 22px 点纹理给空屏以物质感。这是零 UI 库能做到的一致性上限。
2. **Swiss 骨架的屏级模板**：眉标（14px ink-soft）→ display h1 → 说明（15px/24.4）→ `mt-auto` 底部锚定行动区。全部 11 个组件遵守同一模板，扫视成本极低。
3. **每屏至多一个 Primary**：ember 实底 60px 按钮全应用独占「推进」语义；Ghost 只承载回退/次要。主行动从未被稀释（深夜双卡除外，见 P1）。
4. **计时屏的排版纪律**：88px tabular-nums Georgia 数字 + `document.title` 同步 + 时间戳差值计时（与渲染帧率/后台节流无关），工程与设计双重正确。
5. **永不责备的完整落地**（反向 dark-pattern 审计通过）：未记录≠失败（热力图用「未记录」不用红色/叉）、灰色胜利同等计数、`如实回答。这是数据，不是审判`、断链补偿卡、放弃轮`回来就算数`。无虚假紧迫（时间提示全部来自真实时间门控）、无无限滚动（已完成 slice(0,10)）、无社交比较、无内购广告。
6. **状态机式时间门控**：同一 URL 在 9/14/16/21/23 点呈现五个不同界面，走查全部按预期切换；「状态优先、时间窗只给默认值」的领域内核是对的。
7. **防御性交互细节**：maxLength 全覆盖、保存中禁用+防连点、错误态+重试、乐观更新、运行中会话刷新恢复、晚间步骤 sessionStorage 断点续走、SW 自动更新。
8. **快捷模板 Chip 系统**：交付物模板/降级建议/历史规则三处复用，把「写什么」的成本压到一次点击。
9. **热力图表达**：三态+图例+月计数+44px 格子+aria-label，是数据可视化克制的正确答案，不要加圆环/火焰/连击特效。

## 三、改进清单（按影响力排序）

**P1 · 深夜双 CTA 重复，收束感被稀释**
- 位置：`App.tsx` L207–215（notice 卡）+ `TodayCard.tsx` L61–71（lateNight 应急卡）
- 现状：23:00 MIT 已定屏，实测两张 ember 卡同文案并置（顶部 46px「还有时间做一个 10 分钟版本 →」+ 正文 83px「还有时间做一个 10 分钟版本。」）；`开始一轮专注` 仍占 Primary 位
- 建议：`view==='now' && lateNight` 时二保一——保留 TodayCard 内的详细卡，删顶部 notice；同时该模式下把`开始一轮专注`临时降级为 Ghost，应急卡成为唯一 ember 元素。改动约 10 行。
- 为什么：层级与扫视——深夜的界面应比白天更收束（「只剩一件事可做」），现在是全应用注意力竞争最严重的一屏。

**P2 · 晚间流程进度指示碎片化**
- 位置：`EveningFlow.tsx`（眉标 `晚间复盘 · n/5` / `前夜清障 · n/3`，TRIAGE 与 DELIVERABLE 两屏无步数）
- 现状：实测旅程最多 10 屏、三套计数器（n/5 → 无 → 无 → n/3），中段两屏进度感断裂
- 建议：统一为 `晚间 · n/7`（复盘记 1 步、MIT 处置 1 步、成果 1 步、前夜 3 合 1 记 1 步……以「环节」而非「屏」计数）；并在眉标行下加 4px 高、ember、宽度 = n/7 的进度条（`transition: width 250ms cubic-bezier(0.2,0,0,1)`）。应急流已有统一的 1/3–3/3，照搬即可。
- 为什么：progressive disclosure——7 步向导的「还剩多少」是用户坚持下去的导航信息；目前计数器重置比没有计数更伤。

**P3 · 胜利时刻零反馈强度**
- 位置：`WinMoment.tsx`（静态渲染，唯一 CTA 是 Ghost）
- 现状：记录首个交付物后硬切入 60px「我赢了。」，无动画、无触觉；全应用 `styles.css` 中 animation/keyframes 计数为 0（grep 实证），动效词汇表只有 `active:scale-[0.98]` + Tailwind 默认 150ms 状态色过渡
- 建议：值得一次（且仅一次）入场动效——h1 `@keyframes win-in { from { opacity:0; transform: scale(0.92) } }`，320ms `cubic-bezier(0.34,1.56,0.64,1)`（spring 感），成果卡延迟 80ms 淡入；同时 `navigator.vibrate?.([30,50,30])`。不做粒子/撒花——一次弹性缩放+触觉就是这个纸面美学的上限。
- 为什么：动效与转场——全应用唯一的多巴胺峰值时刻目前是最安静的一屏；反馈强度应与事件稀缺性（一天一次）匹配。

**P4 · 触控目标与低对比小字（成组修复）**
- 位置：`App.tsx` header、`WinWall.tsx` 月份导航/删除按钮、`TodayCard.tsx` 今天崩了
- 现状（全部实测）：header `成果墙` 40×16px；月份导航 ‹› 32×34px；`今天崩了` 高 24px、ink-soft/70 对比度 **2.67:1**；12px ember 链接 3.85:1、12px moss 连胜 4.13:1（AA 均要求 4.5）
- 建议：header 链接加 `py-2`（≥32px 高）并升到 14px；‹› 改 `min-w-[44px] py-2`；`今天崩了` 改 `text-[15px] py-1.5` 且颜色升为 ink-soft（4.57:1）；12px 的 ember/moss 文字统一升到 14px 或把令牌加深（如 `--color-ember-deep: #a34f12` 供小字使用）。PrimaryButton 文字 18px semibold 对 ember 底为 3.85:1，属可接受的边缘（按钮大底色强），不必动。
- 为什么：拇指工效 + affordance——这是全应用唯一成批违反 HIG 44pt / WCAG AA 的地方，且都在高频路径上。

**P5 · 成果墙页签计数导致折行、行高跳变**
- 位置：`WinWall.tsx` L157–171（`flex gap-2` 页签行 + `ml-auto` 连胜数字）
- 现状：实测有计数时页签行 54px、无计数 34px——总宽超 342px 后页签文字折行、整行被 stretch
- 建议：页签加 `whitespace-nowrap flex-shrink-0`；`当前连胜 n 天` 移出该行（并入「本月 x 胜」那一行，或放 header）。
- 为什么：层级稳定——导航控件不应因数据变化改变几何；这是 5 分钟修掉的实锤 bug。

**P6 · TodayCard 入口密度与时间门控不一致**
- 位置：`TodayCard.tsx` L78–96 + `App.tsx`（`onStartEvening` 无条件传入）
- 现状：14:00 即显示`晚间流程 · 排好明天`（复位列时间窗 `resetOpen` 做了门控，晚间没做）；`直接记录交付物`与专注流终点（到点屏）功能重叠；5 入口等宽铺开
- 建议：① `hour < EVENING_OPEN_HOUR && !day.eveningDone` 时隐藏晚间入口（或降为 12px 文字链）；② `直接记录交付物` 从 Ghost 降为与`今天崩了`同级的文字链（正常路径由到点屏引导，快捷记录是边缘入口）；最终常态 = 1 Primary + 复位 Ghost（窗口内）+ 2 文字链。
- 为什么：progressive disclosure——复位窗证明了「入口按时间出现」是本应用已有的正确模式，把它补齐到晚间即可；等宽按钮越少，Primary 越成立。

**P7 · 午间复位卡溢出首屏**
- 位置：`ResetFlow.tsx`
- 现状：scrollH 917 > 844，`先退出` 底部 25px 在首屏外（实测 815–869）
- 建议：两行说明文案合并为一句 14px；`铁律` 卡改为一行 `text-xs` 内联；label 的 `mt-4` 收为 `mt-3`。目标 scrollH ≤ 844，Primary 完整可见。
- 为什么：单屏可扫——这是 11 个组件里唯一溢出的表单，而它恰恰是「低能耗换挡」定位的屏。

**P8 · 首次体验：安装卡抢占仪式 + 无价值主张**
- 位置：`InstallGuide.tsx` + `App.tsx` L216
- 现状：首屏实测为「品牌行 → 安装卡（5 行文字+2 链接）→ 晨间第 1 步」，产品的核心承诺（一天只做一件事/可见交付物才算赢）直到第 4 屏才出现
- 建议：① 晨间/压缩晨间模式下不渲染安装卡，移到 MIT 完成后的 TodayCard 首次渲染时；② header 下加一行 12px ink-soft tagline（如「一天只做一件事 · 做出来才算赢」，manifest description 里已有现成文案）；③ `知道了` 加 `py-1.5` 扩大触控。另注意：安装卡 dismiss 后 `开启应用内提醒` 永久不可再达——把通知开关补一个入口到成果墙数据区（一行按钮）。
- 为什么：空态与首次体验——新用户 10 秒测试目前答不出「这是什么、对我承诺什么」。

**P9 · 计时屏无总量参照**
- 位置：`FocusFlow.tsx` 计时视图、`EmergencyFlow.tsx` 计时视图
- 现状：88px 剩余时间孤字，不知道 25 分钟走到百分之几（应急 10 分钟同理）
- 建议：数字下方加 160×3px 进度轨（paper-deep 底 + ember 填充），用 CSS `transform: scaleX()` + `transition-duration = 轮长` 线性收缩，JS 只设初值——一行 div + 一个 style。不做圆环（与纸面直角美学冲突）。
- 为什么：数据可视化克制——Streaks/Linear 的进度语言是「一条线」，不是表盘；剩余时间有了分母，焦虑反而下降。

**P10 · 动效语言未成体系（零 token）**
- 位置：`styles.css`（无任何自定义动画/变量）+ `FocusFlow.tsx` 卡住了 sheet
- 现状：视图切换全部硬切；底部 sheet 瞬现瞬灭；notice 卡出现无过渡；全应用 grep `animate-|duration-|ease-` 为 0
- 建议：在 `@theme` 定 3 个令牌：`--ease-out: cubic-bezier(0.2,0,0,1)`、`--dur-fast: 150ms`、`--dur-med: 250ms`；先落地两处——① 卡住了 sheet：容器 `translate-y-full→0` 250ms + 遮罩 fade 180ms；② 视图容器（App 的 body 包一层）`opacity 0→1` 150ms。都纯 CSS。P3 的 win-in 共用 `--ease-spring: cubic-bezier(0.34,1.56,0.64,1)`。
- 为什么：动效与转场——「生硬感」集中在容器级切换而非按钮级（按钮已有 press 反馈）；三个令牌+两处落地就足以建立统一语言，之后所有动效免费对齐。

**P11 · If-Then 前缀重复的文案系统缺陷**
- 位置：`EveningFlow.tsx` If-Then placeholder（「如果明早想拖延，我就…」）vs `MorningRitual.tsx` L77（`如果想拖延：{relay.ifThen}`）
- 现状：实测渲染出「如果想拖延：如果想拖延：只写 5 分钟开头」；规则库 Chip 原文回显同样带「如果」
- 建议：晨间锚点卡去掉「如果想拖延：」前缀，改为引用样式直接呈现原文；或 placeholder 改为「就先启动计时器，只做 5 分钟」（教用户写「就…」半句）。二选一，5 分钟。
- 为什么：文案系统一致性——教练话术的「同一句话只说一遍」。

**P12 · 返回手势/历史栈缺失**
- 位置：`App.tsx`（view 为纯 useState，grep pushState/popstate = 0）
- 现状：成果墙/子流程内的 Android 返回键或 iOS 侧滑会退出 PWA 而非回到主页（成果墙有可见`关闭`兜底，专注/晚间有`先回主页`兜底）
- 建议：`setView` 非 `'now'` 时 `history.pushState({view})`，监听 `popstate` 回 `now`。约 15 行，三个流程统一受益。
- 为什么：平台惯例——PWA 借镜 HIG/Material 最重要的免费正确性。

**P13 · safe-area 声明了 viewport-fit=cover 却没消费**
- 位置：`index.html`（`viewport-fit=cover`）+ `App.tsx` 容器 `pb-8 pt-8`、`FocusFlow.tsx` sheet `pb-10`
- 现状：grep `env(` 全仓为 0；全面屏 Home 条区域全靠 32px padding 硬碰（当前 844px 设备实测按钮底距视口底 48px，勉强安全；更小屏会贴边）
- 建议：容器改 `pb-[max(2rem,env(safe-area-inset-bottom))]`、`pt-[max(2rem,env(safe-area-inset-top))]`；sheet `pb-[max(2.5rem,calc(env(safe-area-inset-bottom)+1rem))]`。另可加 `overscroll-behavior-y: contain` 防误触下拉刷新打断仪式。
- 为什么：拇指工效/平台——一行 CSS 买断全面屏适配。

**P14 · 23:00 无 MIT 时 quick-start 与应急提醒同屏竞争**
- 位置：`App.tsx` notice + quick-start 模式
- 现状：实测 23:00 空 day：ember 提醒卡（10 分钟版本）+「今天只做一件事」表单同屏
- 建议：`lateNight && !day.mit` 时压缩版标题改为「还来得及：写一个 10 分钟能完成的」，并把模板 Chip 换成 `EMERGENCY_CHIPS`；或者干脆直接渲染应急入口卡（写 10 分钟版=事实上的 MIT）。
- 为什么：层级与扫视——深夜的界面应该收缩为一个动作，而不是两个仪式抢人。

**P15 · 热力图/连胜的「今天」钩子**
- 位置：`WinWall.tsx`
- 现状：空态/断链态解释了规则，但没有把视线引向「今天这一格」
- 建议：今日格已有 `ring-1 ring-ember/50`，空态时在其正下方加一句 12px ink-soft：「今天这一格，从一次 25 分钟专注开始」+ 文字链`回到今天`。仅在 `chain===0 || 本月 0 胜` 时出现。
- 为什么：空态与首次体验——数据视图的空态应输出行动，而非只输出规则。

## 四、简约视角 Top 5（只改 5 处）

1. **深夜收束（P1）**：删顶部 notice 卡、应急卡成唯一 ember、专注降 Ghost——产品价值观最关键的时刻，当前是视觉最混乱的时刻。改动最小、立场最大。
2. **晚间统一进度（P2）**：`晚间 · n/7` + 4px 进度条。10 屏旅程的完成率问题，一条线解决。
3. **胜利时刻入场（P3 + P10 令牌）**：320ms spring 缩放 + 双脉冲振动，顺带建立 `--ease-spring/--ease-out/--dur-*` 三个动效令牌。一天一次的事件配一次动效，这就是「less, but better」的 better。
4. **触控与对比度成组修复（P4）**：header 链接、‹›、今天崩了、12px ember/moss——四处高频小目标一次清零，全部是值级改动（padding/字号/色值）。
5. **入口门控补齐（P6 + P5）**：晚间入口按 20:00 门控、直接记录降为文字链、页签 nowrap——TodayCard 回到「1 Primary + 1–2 Ghost + 2 链接」的 Rams 常态，成果墙导航停止抖动。

**总评**：这个产品在结构层面（状态机、令牌、屏级模板、文案伦理）已经达到了单人作品罕见完成度；欠的不是设计系统，而是「最后一毫米」——深夜的收束、进度的感知、胜利的强度、拇指的尺寸。全部 15 条建议都在现有 Tailwind+CSS 栈内、单人可落地，其中 9 条是纯值级改动。
